# Decisions

Choices made where SPEC.md was ambiguous or had to be adapted. Newest last.

## Milestone 1 – Skeleton

- **Spring Boot 3.5.16, Gradle 9.9.2.** "Spring Boot 3 (latest stable)" read as the newest 3.x release on Maven Central at build time (2026-11-24); Gradle is the current release.
- **Java 21 bytecode via `options.release = 21`, no toolchain.** A Gradle toolchain would require a local JDK 21 or an auto-provisioning plugin (an unlisted dependency). Compiling with `--release 21` on any JDK 21+ produces Java 21 bytecode and API checks; CI and the Docker build both use JDK 21.
- **No frontend stage in the Dockerfile yet.** `frontend/` does not exist until milestone 6, and `npm ci` fails without a `package.json`. The node stage from the spec is added with the frontend.
- **`bootJar` named `llm-cost-tracker.jar`, plain `jar` disabled,** so the Dockerfile copies one known file instead of a glob.
- **Readiness includes the database.** `/actuator/health/readiness` reports DOWN when Postgres is unreachable; liveness does not depend on it. Health details are hidden (`show-details: never`), since the endpoint is public.
- **Admin password validated at startup** with Bean Validation on `TrackerProperties` (empty or < 12 characters → startup fails). Added in milestone 1 because the compose file already requires the variable.
- **CI runs the compose stack.** Besides `./gradlew test`, the CI `docker` job builds the image, runs `docker compose up`, waits for the container healthcheck and counts the seven tables — the milestone 1 acceptance check, automated.
- **Healthcheck uses `wget`.** Checked on 2026-11-24: `eclipse-temurin:21-jre` (Ubuntu 26.04) ships `/usr/bin/wget` (but not `curl`), so the spec's healthcheck works without extra packages.
- **JVM default time zone pinned to UTC** in `main()` and in the test JVM. The spec stores all timestamps in UTC; also, pgjdbc sends the JVM zone on connect and Postgres 16 rejects legacy aliases such as `Asia/Calcutta`, which broke startup on such hosts. Budget periods will use `TRACKER_TIMEZONE` explicitly.
- **Compose image is `llm-cost-tracker:latest` for now.** The spec's `ghcr.io/OWNER/...` placeholder is rejected by Docker (repository names must be lowercase). Milestone 9 switches it to the real GHCR path once the owner and project name are settled.
- **Dependabot ignores major bumps of Spring Boot and `eclipse-temurin`.** The spec pins Spring Boot 3 and Java 21; Dependabot opened 3.5→4.2 and 21→25 PRs on the first run. Minor and patch updates still flow.
- **`.env` also passed to the app via `env_file` (optional)** so any `TRACKER_*` variable added to `.env` reaches the app without editing the compose file.

## Milestone 2 – OpenAI non-streaming proxy

- **OpenAI usage fields verified on 2026-11-24** against the API reference (developers.openai.com, Chat object). `prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens` and `completion_tokens_details.reasoning_tokens` match the spec. The reference also lists `prompt_tokens_details.cache_write_tokens`, which the spec says OpenAI does not have; it is **not recorded** in v0.1 (the docs do not say whether it is billed separately or included in `prompt_tokens`). Revisit when OpenAI documents its billing.
- **Fixtures are real-shaped, not captured.** `fixtures/openai/*.json` follow the documented `ChatCompletion` schema with made-up IDs and counts. They are pretty-printed on purpose, so the byte-identity test would catch any re-serialisation.
- **The SDK test also sets `X-Tracker-Key`.** With `TRACKER_REQUIRE_PROJECT_KEY=true` (the default) the project key header is needed. SDKs set it as a default header in client config (`putHeader`, `default_headers`), so the calls themselves are unchanged.
- **Without a key and with `TRACKER_REQUIRE_PROJECT_KEY=false`, calls are forwarded but not recorded,** because every `usage_event` needs a project. The simplest option; revisit if users want a default project.
- **`Accept-Encoding` is removed only on recorded calls,** so the upstream answers uncompressed and the side copy can be parsed. The client still receives exactly the bytes the upstream sent. Other paths keep the client's `Accept-Encoding`.
- **Streaming requests (`"stream": true`) and `text/event-stream` responses are relayed but not recorded** until milestone 5.
- **Project keys are cached in memory,** refreshed every 30 s and on each cache-miss lookup, so known keys keep working while Postgres is down. An uncached key that cannot be checked because the database is down gets **503 `tracker_unavailable`**, not 401. Keys are looked up by their SHA-256 hash; comparing digests this way leaks nothing useful through timing, so no separate constant-time compare is added.
- **Upstream connection failures return 502 `upstream_unavailable` (504 `upstream_timeout` on timeout) and are not recorded**, since no upstream status or usage exists.
- **Recording parses after the last byte is sent** (`doFinally` on the relay), so it never delays the response. Latency is measured to that point. A client disconnect marks the event `incomplete`.
- **The batch writer loads the whole `model_price` table once per batch.** The table is small, and this keeps prices current with no cache to invalidate.
- **Hikari `connection-timeout` lowered to 5 s** so the writer notices an outage fast and drops (and counts) the batch rather than blocking for the 30 s default.
- **Project key CLI is `--create-project=<name>`.** When that flag is present the app starts without a web server, prints the key once to stdout, and exits (code 0; 1 for a duplicate name; 2 for a bad name).
- **Redacting log converter** replaces Logback's `%m`/`%msg`/`%message` (`logback-spring.xml`). It masks `Authorization`, `x-api-key` and `X-Tracker-*` values, bearer tokens, and `sk-…`/`trk_…` keys. The proxy never logs these on purpose; the converter is the safety net the spec asks for.
- **Test-only dependencies added: `com.openai:openai-java` 4.112.0 and OkHttp `mockwebserver` 4.12.0** (pinned: Spring Boot 3.5 no longer manages OkHttp; 4.12.0 is the OkHttp version the SDK uses). Both are named in the spec's Testing section. A small `Await` helper is used instead of adding Awaitility.
- **Custom OpenAI-compatible providers (`TRACKER_CUSTOM_PROVIDERS`) wait for milestone 3**, as the spec's milestone list says.

## Milestone 3 – Anthropic, Responses API, custom providers

- **Anthropic usage fields verified on 2026-11-26** against the Messages API reference and the prompt-caching guide (platform.claude.com). `input_tokens`, `output_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens` match the spec. The docs define total input as `cache_read_input_tokens + cache_creation_input_tokens + input_tokens`, so `input_tokens` excludes cached tokens and is **stored as reported**. If `cache_creation_input_tokens` is missing, the per-duration breakdown `cache_creation.ephemeral_5m_input_tokens + ephemeral_1h_input_tokens` is used.
- **One cache-write price per model in v0.1.** Anthropic's docs price cache writes by duration: 5-minute entries at 1.25× the base input price, 1-hour entries at 2×. `model_price` has one `cache_write_per_mtok` column, and the seed file (milestone 8) will fill it with the **5-minute** price, Anthropic's default. 1-hour writes are therefore under-costed. Listed in the README under known limitations. A later migration can add a 1-hour column priced from `cache_creation.ephemeral_1h_input_tokens`.
- **Anthropic `output_tokens_details.thinking_tokens` is stored in `reasoning_tokens`** for display only. The spec's table says Anthropic has no reasoning field, but the current docs report one. Thinking is billed as output and is already inside `output_tokens`, so cost is unchanged.
- **Responses API usage fields verified on 2026-11-26** (developers.openai.com, Responses object): `usage.input_tokens`, `usage.output_tokens`, `usage.input_tokens_details.cached_tokens`, `usage.output_tokens_details.reasoning_tokens`. The reference page does not say whether `input_tokens` includes cached tokens. The spec says it does (as for Chat Completions), so the cached part is subtracted. The reference also lists `input_tokens_details.cache_write_tokens` (with 30-minute and 12-hour breakdowns). Like Chat Completions' field (milestone 2), it is **not recorded** in v0.1, because the docs do not say how it is billed.
- **Only `POST` to the exact endpoint path is recorded.** `GET /responses/{id}` is forwarded but not recorded, since it would double-count the original call. So are `/v1/messages/count_tokens` and `/v1/messages/batches` (batch APIs are out of scope).
- **Custom providers parse as OpenAI and are priced under their own name.** `usage_event.provider` is the configured name (e.g. `groq`), so a custom provider needs its own `model_price` rows. It never borrows OpenAI's prices, because the same model name can cost differently on another host.
- **`TRACKER_CUSTOM_PROVIDERS` is validated at startup.** Names must be lowercase slugs (`[a-z0-9][a-z0-9-]{0,31}`) and may not reuse `openai`/`anthropic`. URLs must be absolute `http(s)` with a host and no credentials, query or fragment. Any mistake stops startup rather than silently routing traffic elsewhere.
- **Integration tests share one Spring context** (`ProxyIntegrationTestBase`, with three MockWebServers for OpenAI, Anthropic and a custom provider), so the slower context start-up happens once.
- **Test-only dependency added: `com.anthropic:anthropic-java` 3.14.0** (uses OkHttp 4.12.0, the same as `openai-java`).
- **Dependabot PR #7 (mockwebserver 4.12.0 → 5.5.1) left open.** MockWebServer 5 pulls in OkHttp 5, while both provider SDKs are built on OkHttp 4.12. Recommend closing it and ignoring OkHttp major bumps until the SDKs move.
- **Anthropic credentials pass through in whichever header the client uses.** `anthropic-java` 3.14.0 sends `Authorization: Bearer …` (as the current API reference shows) rather than `x-api-key`. The proxy forwards both untouched and never logs either. Tests cover both forms.
